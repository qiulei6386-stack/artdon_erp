# 决策记录

1. **独立目录**：把故障和删除范围限制在 `commercial_center_v1/`，旧系统无需依赖它。
2. **共用数据库**：用户确认沿用实际生产库 `artdon_new_erp`，避免复制账号和业务主数据。
3. **`cc_` 前缀**：提供明确表级所有权、审计和回滚边界。
4. **旧表第一阶段只读**：在字段含义、生命周期和权限边界完成审计前禁止回写。
5. **适配器模式**：旧字段变化只影响单一适配层，页面不散落旧表 SQL。
6. **不改旧菜单**：入口故障不会影响旧导航，删除新目录即可停用。
7. **不建立第二账号系统**：读取旧 Session 和账号，不复制密码。
8. **不调用旧 `has_permission()`**：其临时权限过期路径可能写旧表；V1 用参数化只读查询实现权限快照判断。
9. **受控执行迁移**：先交付 dry-run、SQL 和回滚方案；用户于 2026-07-24 明确批准后，通过仅限 CLI 的白名单执行器创建 4 张基础 `cc_*` 表，Web 自动迁移仍关闭。
10. **后续可调整**：细分权限键、只读字段白名单、跨服务器认证协议和 `cc_*` 业务表，均需下一阶段审计批准。
11. **总规范路径**：用户指定的 `docs/commercial-center/ARTDON_COMMERCIAL_CENTER_MASTER_SPEC.md` 不存在；采用实际同 SHA 文件 `commercial_center_v1/ARTDON_COMMERCIAL_CENTER_MASTER_SPEC.md`，不在旧目录另建副本。
12. **M1 数据范围**：普通用户只读取本人创建/负责的派工，以及用户名或真实姓名匹配的报价、订单和日志；超级管理员可读取汇总范围。
13. **M1 操作边界**：运营首页只做识别与导航，正式处理动作返回旧系统，不在新模块回写。
14. **M2 权限**：产品页要求实际旧权限 `naming.view`，物料页要求 `bom.view`；未登录或无权限时不查询数据。
15. **M2 敏感字段**：物料页面不查询采购价格和供应商；成本权限与正式编辑留待后续模型评审。
16. **无浏览器实例**：HTTP、PHP、查询和响应内容已自动验证；1440/1920 人工视觉验收保留为待办，不用其他浏览器工具绕过。
