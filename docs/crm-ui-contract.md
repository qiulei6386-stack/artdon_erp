# CRM 统一界面与操作规则 v1

状态：2026-09-06，分阶段实施规范，不表示全系统已经迁移。

## 页面与视觉

- 共用导航、搜索筛选区、列表、详情、弹窗与状态反馈；保留数据工作台、邮件阅读、分步执行三种业务模板。
- 先以客户页面为基准，再迁移邮件/任务，随后推广、拜访、商机、AI、雷达。
- 复用现有主题变量及个人显示偏好，不在模块末尾叠加硬编码颜色/按钮高度覆盖。深浅主题、紧凑/舒适密度都需验收。
- 同一层级只有一个突出主操作；普通操作降级显示，低频功能收进“更多”。危险操作与普通操作分开，执行前说明对象和范围。
- 加载、无数据、无权限、网络失败必须区分；错误保留输入并给出可操作的重试路径。
- 手机切为卡片/独立详情，避免缩小整张桌面表格；键盘焦点、ESC 关闭和可读对比度列入验收。

## 操作身份与权限

- 第一批注册在 `crm_action_contract.php`，按模块生成稳定动作 ID；中文按钮名只是兼容别名，不能跨模块决定权限。
- 例如任务的“标记完成”使用 `task.complete`，推广同名操作使用 `promotion.execute`；“创建派工/生成派工”都路由到同一个实际处理器。
- 侧栏、列表和详情入口共用权限和状态判断，点击时再次校验；服务端仍负责最终授权，前端隐藏不是安全边界。
- 推广编辑保留原编辑权限，并要求实际保存接口的 `promotion.task_create` 权限，避免显示可以执行但保存必被拒绝的按钮。
- 没有实现的功能不进入主要操作区；必须展示时，禁用并说明原因。不能只有弹窗提示“待接入”却显示完成。
- 第一批之外的旧标签权限映射仍存在，后续按模块迁移，不宣称全量完成。

## 数据与异步反馈

- 客户详情、表单实体、当前选择必须一致；只允许最新请求影响当前视图。
- 关闭或替换弹窗就是取消该弹窗的展示意图，旧响应不能再次打开它；这不等于撤销已发出的服务端写入。
- 保存按钮请求期间禁用；新建样品使用持久表单标记，重试返回同一记录，新表单可创建真实第二单。
- 上传和业务保存是两步：先保存成功就保留记录 ID，上传失败不能让下一次点击重新新建业务单据。
- 已受理、待执行、执行中、真实成功、失败、跳过、取消分别显示；入队不代表邮件送达，人工渠道不得由系统自动宣称完成。
- 暂停不再领取新邮件；取消清理待发队列；已经被领取的在途邮件无法保证撤回。确认框必须提前说明。
- 有发送队列或执行历史的项目不能通过向导重建目标；使用复制项目，保留历史。名单读取失败不能打开空名单编辑器。

## 后续迁移验收

每个模块须通过：角色权限、正常操作、连续点击、失败重试、快速切换、取消/关闭、浏览器刷新、桌面/手机、深浅主题、键盘操作。优先基于共用组件消除重复实现，再移除确认无调用的旧代码；不以改色或新增样式覆盖作为统一完成的依据。
