# 待办日报

## 使用

待办顶部右侧「今日总结」。电脑右侧面板，手机全屏；日期/人员/关闭固定，内容区域单独滚动。六类卡片可切换，每页20条；任务名称打开现有详情，关闭详情回到总结原位置。普通账号只查自己，后台拒绝任何他人ID或全员参数；管理员可选全员或某人，私人任务也在管理员授权范围内。

- 今日完成：所选日期完成且日终/当前仍为完成的个人任务实例。取消不算完成，重新打开后归未完成；原始完成时间缺失的旧任务不猜日期。
- 应办未完成：截止日为所选日；无截止时间按任务日期。更早的未完成任务单列逾期，不重复加到当天应办。待接收、暂停、待确认、退回/拒绝均未完成。
- 明日待办：下一日到期的未完成任务。更远任务归其他进行中。
- 今日变更：真实入库的新增、状态/负责人/截止日期/重要字段变更、删除，以及新增/修改/删除的文字进度。显示修改前后值和操作人；转派涉及双方，双方日报各显示一次，全员明细只计一次。归属边界不向普通账号暴露他人旧私人正文。长文本截取前400字，完整内容到任务详情查看。
- 按实际负责人归属，不将自己派给他人的任务算成自己完成。多人派工按每人实例计数，不再把母任务加算一次。私人/个人/单人/多人/计划/周期/固定的已生成任务实例都使用同一口径；尚未生成的未来周期任务不预测。
- 本人补充：只可填写自己当天的未完成原因/协作需求，约1000字。管理员看他人说明只读，历史只读；版本冲突拒绝覆盖，失败和切换时保留输入。保存有会话CSRF校验。

## 历史与记录

独立 `dispatch_daily_events` 保存任务写入前后快照，MySQL触发器与实际写入同事务；原业务操作日志的五分钟合并不再决定日报事实，回滚不会留下假的工作成果。读消息、排序、提醒计数不记入成果。文字进度单独捕获，删除后保留删除事实；附件、步骤和规则母板管理仍在原详情/审计查看，本日报不声称涵盖所有管理动作。

任务字段的历史按所选日北京时间24:00前最后一次已记录状态还原，而不是拿当前表替代。采用持续变更快照，不依赖某个人午夜打开页面，也不额外配置发通知的定时任务。原日期之后的普通改期、转派、删除不会重写原日期的任务数据。历史打开详情仍展示当前任务，可能因删除/权限变更不可打开；日报中当时记录仍保留。人员名称使用当前人员目录。

上线时为现存任务建立一次初始状态，不修改业务任务。首日明确标记变更只覆盖启用后的时段；此前日期不可选择，不凭已有零散日志补造。任务原有当天完成时间可纳入首日完成数量。持续事实的时间为UTC，展示/日界限固定北京时间；不要通过手工回拨数据库时钟或更改日志时间改写审计。长事务跨午夜的提交不属于“准点定时归档”承诺。

## 运维与验证

新增3表、任务表3个触发器和进度表3个触发器。仅在已发布提交上显式执行 `php tools/install_dispatch_daily.php --install`；脚本限定CLI、取得初始化锁、校验已有触发器定义、对任务行取短事务初始快照，重复执行不重复建基线。失败停止并保留错误，不覆盖未知触发器。页面请求不做日报DDL。

日报查询使用独立一致性只读事务，主表不写入。只点开时查询，分页结果有完整数量；管理员全员统计以同一次读取为准。新表应纳入整库备份；原待办业务备份恢复保留日报历史，不把旧业务备份当作审计归档。恢复/回滚代码时不可随意删除新事实表；触发器为只追加记录且兼容原任务结构。
