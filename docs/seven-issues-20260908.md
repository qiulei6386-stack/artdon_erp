# 七项问题修复与验收范围

## 改动

| 项目 | 根因与修复 |
| --- | --- |
| 1 拼箱数量、规格 | 箱内数量被当成额外产品再次累计，自由文本首词被误当型号。产品行统计实际出货数量，拼箱行仅说明已包含的内容和包装；完整保留说明，不猜型号。保存、页面合计、PL 与 Excel 使用同一数量口径。旧批次摘要通过只读明细汇总显示，不批量改写历史。 |
| 2 客户群不显示 | 轻量详情返回空群列表，但连续档案布局直接显示该区域，未触发分栏加载。概览读取当前客户的群资料并标记已加载，沿用客户权限，不查询跨系统重型资料。 |
| 3 合并出货选择 | 新增订单勾选；取消勾选保留临时填写但不提交。后端按实际正数量产品确定关系、尾款检查和主订单，编辑也移除零数量订单关系。创建整体写入事务；无产品明确拒绝，不静默生成全部产品。 |
| 4 PDF 空白 | 有效 PDF 保存为通用二进制 MIME，预览仍原样返回。检查 PDF 文件头后返回 application/pdf；页面检查返回类型和错误，有加载、异常、下载和新窗口入口，关闭时中止请求并释放临时对象。 |
| 5 自己的回复丢失 | 解码后的回复 HTML 含旧邮件 Content-Type 标签，被再次当原始 MIME 拆解，前面的回复被丢弃。只识别开头的有效 MIME 头区，保留已解码正文。 |
| 6 同一邮件只显示后段或签名 | 完整 HTML 的 meta 标签触发同一错误拆解。采用同一修复；不再凭正文内的 =HH 对已解码内容二次解码。两种原始正文结构均验证完整保留，不修改存储邮件。 |
| 7 确认超时但实际执行 | 响应丢失不等于事务失败。新增受权限保护的只读确认状态；超时先核实，结果未知保留确认标识并禁止编辑重建预览，可核实或安全重试同一预览。复用已存在事务行锁保证一次入队，列表刷新失败不再误报确认失败；复用批量语句降低重复开销。 |

## 使用注意

- 产品行填实际总数量，包括拼箱中的产品；产品行的包装指标只填常规箱。全部拼箱时，常规箱数、重量、体积为 0，在拼箱区登记包装指标。
- 合并出货默认只勾选入口订单，额外订单需明确勾选。取消勾选不清空临时输入。
- 推广“已确认”只表示安排进入队列，实际送达需查看发送状态；超时后不要另建重复推广。
- 没有重发任何真实客户邮件，没有删除、改写历史订单或邮件正文。过往已导出的离线文件不会自动改变。

## 已执行的检查

- 新增纯函数回归覆盖拼箱总数、整箱加拼箱、超量拒绝、完整规格、选择范围、两种邮件正文、MIME 正反例、PDF 类型和不安全附件类型。
- 出货实际保存/编辑/校验 SQL 在一次性 MySQL 实例验证；金融、通知和初始化依赖用测试替身隔离。验证关系、主订单、零数量、越权产品、剩余数量、事务回滚和历史只读投影；不声称已做出货多用户并发测试。
- 推广实际队列/模拟发送回归及新增状态查询、跨用户拒绝、重复确认；3000 对象负载使用合成数据，无正式群发。
- 离线 Chrome 检查推广 25 组布局与确认超时、状态恢复、列表失败；附件请求成功/失败/关闭与出货订单勾选保存，390/1280 宽度。浏览器 PDF 文件传输和预览容器通过；不将此替代所有终端的内置 PDF 阅读器验收。
- 原反馈邮件/PDF只读核对：修复函数保留完整原 HTML，PDF 文件头有效并映射正确类型。
