# 报价与订单读取专项扫描

## 本次发现并修复

| 入口 | 原问题 | 修复 |
| --- | --- | --- |
| 合并出货 | 同客户全部订单、完整快照及行级快照重复加载 | 先取摘要，再逐张请求可出货明细，显示读取进度 |
| 新增/编辑出货 | 打开窗口即重算写回；编辑重复请求一次 | 准备只读，删除重复请求，缺失历史明细明确报错而非自动改写 |
| 保存出货 | 验证数量却读取全部图片；保存再传输完整快照 | 验证只读必要字段，事务内由数据库逐行复制原图/快照 |
| 并发出货 | 两次提交可在保存前同时看到旧剩余数量 | 创建、编辑、删除共享按订单排序的互斥锁，等待后重新校验 |
| 订单详情 | 查看单张仍带三份历史数据；切换时旧响应可覆盖新选择 | 概览明细轻量读取、图片懒加载、保留完整导出入口，旧响应隔离 |
| 订单对账 | 汇总和导出携带无关行级图片快照 | 仅取对账明细及费用判断元数据 |
| PL/CI | 订单全文快照、商品图在 JSON 中反复复制 | 只取抬头所需快照元数据，正文图片独立保留，不在嵌套 JSON 重复编码 |
| 佣金 | 批量同步和修改读取完整订单 | 只取该操作所用标识、金额和币种字段 |

## 不改变的业务规则

- 同客户、同币种、费用项不可出货、剩余数量限制、未收齐款提示。
- 原图、原始订单及出货快照、历史金额；没有压缩或删除原图。
- 保存/审核的版本、改价原因和金额校验；完整报价/订单导出仍按单读取原文。
- 没有提高生产 PHP 内存或数据库参数。
- 旧订单或出货批次明细缺失时停止操作并提示核对，不在打开窗口时猜测并重建历史数量。

## 验证与边界

- 合成数据包含超过 128 MiB 的订单历史字段，在 128 MiB 限制下验证准备、保存、编辑、原图快照逐字一致、费用识别、超量拒绝、事务回滚、跨连接锁和单证数量/金额。
- 前端实际函数验证逐张请求、失败不返回部分结果、恢复按钮、重试、错对象拒绝和订单切换竞态。
- 对原报错案例使用只读事务核验候选函数；它不是完整浏览器发送出货验收，也未修改真实单据。
- 报价首页、保存、审核、转订单及金额既有回归一并复检。
- 本次是针对重复加载、内存与相关操作一致性的专项修复，不代表所有历史业务记录已经核账，也不能保证今后任何输入都不会产生错误。必须实际读取原文的导出/历史归档与摘要查询不同，不能用删减归档内容来换取速度。
