## 当前整体优化（已发布，正式验收待续）

本节覆盖下方历史批次状态。整体优化 `0262a6b` 及正式验收发现的新建商机修补 `b92e482` 均已推送和部署。新建客户正式验证通过；商机修补后的页面、关联任务及受控邮件验收尚未完成，不以部署成功代替全流程验收。

- 邮件查询：已发送去重只读取必要字段，一次排除结果同时供精确计数与分页使用。36 组合成数据完整集合对照通过；现有正式数据只读抽查两组也完全一致。大样本查询 5.46 秒 → 0.92 秒，小样本 0.74 秒 → 0.19 秒；不是整页性能或长期负载统计。
- 邮件发送：先持久化队列再返回，释放会话锁，后台仅处理本次受理任务；保留原定时发送，现有定时器兜底。发送过程原子认领，同表单重试不重复投递。发送失败、回执不明、长时间未更新均可核对，不把入队说成已发出，不自动重发不确定邮件。回复也需要发送权限。网络写入会处理部分写入，DATA 后错误不会伪装成确定未发送。
- 客户资料：总览不再同步读取全部业务联动；按栏目读取并合并，保留客户身份与已读栏目。未读取不显示假零分/假零条；没有评分时显示未知，既有规则评分明确标为估算，成交倾向不冒充统计概率。
- 流程入口：客户/商机带着经服务端授权核对的来源进入真实标准报价页；只带入新报价，不覆盖已保存报价，补充产品并保存才生成报价。“我的待处理”聚合本人可见未完成任务及当前邮箱异常/未回复，复用现有页面。拜访跟进不串客户；拜访派工必须取得真实编号才提示成功。
- 雷达与按钮：搜索结束待核查不再计为执行中，可进入本任务候选；快速切换筛选只接受最新结果。清除额外确认的邮件/推广占位按钮，保留已经有效的填写结果、截图和转人工功能。任务详情不堆放无法执行的按钮。
- UI：共用表单字段、焦点、错误/空状态、操作区及手机折行样式，保留既有主题和用户布局；公共菜单每组最多三个主要操作，低频有效项保留在更多中。不是换框架或重写全部 ERP 页面。

验证：545 个 PHP 文件语法、48 套后端回归；59 个 JS/CJS 语法、13 套前端回归（商机原方法增至 24 项）；独立 MySQL 三个真实并发进程认领发送一次、样品/推广竞争测试；离线 Chrome 公共菜单、手机/桌面商机弹窗及完整 20 秒渐变测试均通过。没有真实邮件发送或历史数据清洗。

仍不能标为全流程验收完成：已新增明确标记的验收客户并确认详情，但设备再次锁屏，后续任务与指定收件端邮件验证未完成。发布与三方一致性结果以 WORK_CONTEXT 最新记录为准。外部 ERP 的 AI 自动生成 PLM/BOM/资料文件不因入口治理而凭空实现；未接通功能不伪造成功。报价跟进邮件的客户端后续绑定仍不是脱离页面的持久化工作流，不能宣称关页后业务联动必然完成。

## 续批：商机关联任务与表单防错

- 从已上线 `dfb132d` 继续。商机“创建样品任务”“创建资料任务”打开统一任务表单，填写负责人、截止时间和说明后，真实写入任务中心，返回任务编号并保留客户、商机、来源关联。可在“我的任务”中查看自己创建的任务；不自动生成寄送单、资料文件、报价或派工。
- 新接口同时校验商机、客户范围和任务创建/查看权限。客户、商机来源编号由服务端读取；同一表单使用独立提交标识和既有任务唯一键，重试复用记录，不能以调用者传入的编号改写其他任务。
- 商机创建跟进复用已有客户身份保护流程；联系人选项不再沿用其他客户。后台拒绝不属于该客户的联系人，并在保存前检查勾选创建跟进的权限。
- 商机列表只接受最新筛选响应；旧表单附件响应不更新新表单；反复打开弹窗不叠加附件点击处理。禁用的未接通选项不随保存提交。
- 商机保存成功后立即保留编号，再上传附件。上传失败重试编辑原商机，不重复执行已确认成功的创建跟进；每份文件独立上传并记住成功项，等待所有在途上传结束后再解锁。旧保存响应不能关闭新弹窗或把新表单的附件上传给旧商机。
- 普通任务编辑未提交来源/客户/商机/报价/状态时保留现值，防止关联清空或已完成任务重开；缺省优先级不再产生警告。
- 验证：56 个 JS/CJS 语法、10 套前端检查（新增 19 项商机原方法场景）；540 个 PHP 语法、45 套后端检查。新增后端测试运行真实业务函数与合成数据库语句，涵盖权限、输入、幂等重试和模拟唯一键竞争；不是本批真实数据库并发压测。
- 离线 Chrome 采用正式主题和弹窗结构，390/1200 宽度、原生关闭、重复点击、失败重试、旧响应隔离、成功附件清除/剩余附件重试通过，零网络请求。主代理查看两种宽度截图。不是正式账号验收。
- 边界：服务器已写入但响应完全丢失时，普通商机保存和附件上传尚无完整服务端幂等协议；不据此宣称任何断网情形都绝对不会重复。未改变历史业务数据、邮件投递协议或其他模块。
