# 推广执行规则与修复说明

## 执行规则

- “按客户偏好”先读取联系人明确设置，没有联系人设置才采用客户主档；最终预览列出来源和覆盖原因。多渠道不猜测、不自动改成邮件。禁联、离职、禁推等限制继续生效。
- 微信个人、WhatsApp个人按联系号码执行；微信群、WhatsApp群展开为真实、有效且允许推广的客户群，同一群只生成一次。没有群和没有负责人分别说明原因。
- 邮件按实际发件账号的签名生成；缺签名阻止预览/确认。均分发送保留逐账号冻结的内容和变量，不读取发送时的新签名替换原预览。
- 邮件发送成功仅以发送队列成功为准，表示邮件服务器已接受，不承诺客户收件或阅读。人工补救不改写原邮件失败事实。
- 人工选择只是选择，必须填写实际联系结果并明确提交。已发送、发送中、待发或重试中的邮件不能勾成人工完成；排除的群对象不能直接标成功。

## 个人待办和提醒

确认推广时，为有效人工对象生成幂等的个人待办，包含负责人、计划开始时间、截止时间和已确认话术；到执行时间提醒。完成个人待办同步推广结果；暂停/取消项目不再生成执行提醒。关联任务不允许单独修改、延期或删除，防止两处状态分离。

人工窗口可按需查看已确认话术，图片仍在原预览中查看；文字显示经过转义。排除项单独说明，不能计入人工待执行数。

## 性能及历史保护

新队列将正文和账号签名作为不可变模板共享保存，每个对象保存冻结变量和模板校验摘要。发送器逐封读取正文，避免批量载入大图片。旧队列兼容读取，不改旧邮件、旧签名、收件人或发送时间；旧压缩器不得以现用模板替换新版确认快照。

历史已确认人工工作可用 CLI 工具 `tools/promotion_manual_backfill.php --task=ID` 先预检，批准后添加 `--apply`。只补缺失的待办，重复执行不重复创建，不触发邮件发送，不展开原排除群，不覆盖已有反馈。执行日志保留补齐目标标识。

历史排除对象须补齐资料后另建补充推广、逐项预览确认。禁止为补遗漏而重跑整个历史任务。

## 验证

合成测试覆盖：联系人覆盖、真实群去重、暂停/禁止推广群、禁推联系人不占用群名额、缺签名、各账号签名冻结、大正文共享、重复确认、人工权限与必填结果、重复提交、撤销、任务中心联动、旧提醒补齐及队列不变。

独立禁网络 MySQL 验证事务、并发队列领取、暂停/取消与回滚；SMTP使用模拟，不向客户发送。离线浏览器验证五种宽度、短屏、变量插入、签名检查、分页预览、提示关闭及人工结果操作。离线通过不等于正式用户页面已验收。
