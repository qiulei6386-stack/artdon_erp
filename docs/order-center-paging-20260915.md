# 订单中心分页与慢查询修复

## 原因与范围

原列表一次读取最多 2000 单、前端全量筛选。出货数量汇总反复对含内嵌图片的明细 JSON 做字符串匹配；正式只读诊断中该查询超过 8 秒。重复的列表与看板加载进一步放大延迟。详情此前已按单读取，本轮不改历史订单、审核快照、原图及真实出货。

## 修改

- 服务端筛选、排序、20/50 单分页；关键词按订单号、报价号、客户和负责人查全库，多个词同时匹配。日期、客户、负责人、币种及状态保持可组合，分页排序追加 ID 保证同日稳定。
- 列表只投影数值和名称，不加载图片/快照。费用行增加存储生成标记及覆盖索引，严格复用旧列表分类表达式，写入明细时自动维护；不因草稿改动或新增入口漏更新。旧列表接口兼容且复用标记提速。
- 当前筛选的金额、已收、欠款和全局看板独立聚合，不能用当前页相加。筛选字典来自全部订单。历史 SO-/AT- 编号兼容；旧单直达按全量搜索再打开详情。
- 首屏/刷新请求合并，快速改变筛选丢弃旧响应，搜索防抖、失败可重试；读取失败不显示上一条件的金额。详情及独立合并出货候选分页保留。
- 筛选区自适应紧凑排列，合计在列表上方，小屏文字换行、操作独立，不预取图片。

## 发布与回滚

先按既定流程提交、推送；服务器只运行已发布提交内的 `tools/quote_order_page_install.php --install-order-page-v1 /www/wwwroot/Artdon/artdon_erp`，再更新应用文件。迁移是一次性增加存储生成列和索引，可能短时等待明细表锁，锁等待限 10 秒；不能在网页请求中做迁移。保留原字段，旧代码可继续工作；回滚应用不必删除生成列，也不应恢复旧业务数据覆盖新单。

## 验收

- `quote_order_page_mysql.php`：真实 MySQL 5.7 隔离库，107 单、20/50 分页、跨页查询、金额/数量/状态逐单与旧版对照、原图/JSON 字节摘要不变、费用标记自动更新、只读事务、SQL 搜索转义。
- `quote_order_page.cjs`：并发重复请求、旧响应隔离、全量合计、失败重试及直达入口；浏览器用实际页面样式和模拟传输测试 390/768/1280 宽度。
- 现有合并出货实际数据库回归在生成列存在时执行：混单、部分、增删、箱内分配、版本、幂等、超量拒绝、锁及回滚。
- 正式发布后只读查看首屏、翻页、搜索、详情和候选，不提交真实出货。后台查询毫秒数与用户整页体验分别报告；隔离测试不能冒充正式投递或业务写入验收。

后续边界：当前全局统计仍需扫描数值索引和小型字典；极大规模时可进一步设计增量账务投影，不能用过期缓存或分页数据替代真实总计。
