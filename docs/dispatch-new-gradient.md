# 新建待办：深红到白，20 秒

## 效果与边界

- 新建保存成功后，以深红 `#991b1b` 为起点，在线性 20 秒内渐变到白色 `#ffffff`。
- 桌面整行（含首格）、手机卡片一致；深色主题也采用相同渐变。渐变期间文字按底色亮度切换白/黑，按钮、到期色点和状态徽标的语义颜色保留；透明操作按钮和输入控件临时加中性背衬，避免文字融入深红底。
- 点击编辑时，输入区恢复原有编辑态文字和背景，整行剩余区域继续渐变；临时提醒颜色不写进富文本内容，避免换行或局部格式操作把提醒颜色保存下来。
- 20 秒结束清除临时填充、字色和左线覆盖，恢复原主题、选中态及到期底色；正常浅色任务恢复白底，逾期提示不永久抹除。
- 约 5 秒调整位置、筛选、后台重画、切换手机/电脑布局只接续剩余时间，不重新从深红播放。多条新任务分别计时。
- 已完成、已取消不播放。失效的服务器“刚创建”标记不会让同一任务反复高亮；页面内保留已到期截止时间，作为防重放记录。
- 新建提醒固定为本次指定配色，旧“新建填充/左线”两个自定义色控件退出设置；其他到期色、每日首次标记和人员配色保留，旧偏好字段不做数据清洗。

## 实现与验证

`dispatch_next.php` 维护每条任务的固定截止时间；`assets/dispatch/recent-create.js` 使用浏览器 CSS transition 过渡不透明填充层，压住旧到期背景/首格阴影的覆盖。不需要逐帧 JavaScript 计算，也不会在结束时重画表格打断编辑。只保存并恢复本次临时改动的样式属性。

```sh
node tests/dispatch_recent_create_runtime_test.cjs
```

12 组计时与保存模型测试已接入普通 JavaScript CI，包含 1000 行的扫描次数上界检查。真实浏览器专项另行显式运行，使用提取的真实页面 CSS、高亮 helper 及原始富文本函数，但只使用虚构任务，不启动应用或访问业务接口：

```sh
NODE_PATH=/path/to/node_modules DISPATCH_TEST_CHROME=/path/to/chrome \
node tests/dispatch_recent_create_browser_test.cjs
```

浏览器需已有 Playwright 与 Chrome，具体路径可用测试文件支持的环境变量指定，不自动下载。测试覆盖真实 20 秒计时、桌面/手机视口、明暗主题、到期底色恢复、按钮可读性及编辑保存；不等同于已验收正式登录页面、实体手机或 Safari。实际测试结果、提交和发布状态见 `WORK_CONTEXT.md`。

本改动从 main 单独建分支，不包含尚未上线的 CRM 候选；页面与新增 helper 必须成套发布。没有修改派工 API、人员可见范围或业务数据。
