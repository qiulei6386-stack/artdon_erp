# 推广中心 V1 设计说明

状态：2026-10-14 阶段 1 已接登录、只读客户和自有分组，见 `docs/PHASE1.md`。向导、试发、审批、入队和执行看板仍是原型，不发送邮件。

## 1. 目标与范围

- 替换独立推广中心 `promotion/`，并逐步替换 CRM 内的推广模块（`crm_marketing*.php`、`assets/crm/promotion-composer.js`）。
- 作为 CRM 按模块重构的第一个模块：独立目录、独立数据表、旧表经适配器访问，客户中心日常使用不受影响。
- 界面全新设计，不沿用 CRM 界面，也不沿用 `material_center_v1/ui/`。

## 3. 权限（统一权限）

### 3.1 使用方式

- 判断一律调用 `has_permission()` / `require_permission()`；数据范围调用 `get_user_scope()`。不按角色名判断，不建 `pm_` 权限表。
- 权限键登记在 `crm_permissions`（`module = 'promotion'`），在权限中心“推广权限”页签分配给角色或个人；个人允许/拒绝、临时授权、权限申请与审批沿用权限中心现有流程。
- 服务端返回每个推广的“可执行动作列表”，页面只显示其中的按钮；每次提交服务端再次校验。

### 3.2 权限键

| 权限键 | 名称 | 状态 | 用途 |
|---|---|---|---|
| `promotion.view` | 查看推广中心 | 已有 | 进入模块、看列表与详情 |
| `promotion.task_create` | 创建推广任务 | 已有 | 新建、编辑、提交、撤回、复制 |
| `promotion.execute` | 执行推广任务 | 已有 | 暂停、继续、停止、取消排期、核对不确定邮件、登记人工结果 |
| `promotion.create_group` | 创建推广分组 | 已有 | 新建分组 |
| `promotion.edit_group` | 编辑推广分组 | 已有 | 重命名、加入/移出客户 |
| `promotion.delete_group` | 删除推广分组 | 已有 | 删除分组 |
| `promotion.move_customer` | 移动推广客户分组 | 已有 | 移动、复制客户到其他分组 |
| `promotion.analytics` | 查看推广转化分析 | 已有 | 统计页（后续） |
| `promotion.export` | 导出 | 已有（目前未使用） | 导出收件对象、分组成员 |
| `promotion.manage` | 管理推广 | 已有 | 推广设置（免审额度、频控、时间窗、邮箱日上限） |

| `promotion.exempt_small` | 小批量免审 | **新增** | 第 4 节小批量免审 |
| `promotion.use_any_mailbox` | 使用他人或公司邮箱发送 | **新增** | 选择非本人邮箱（仍需审批） |

### 3.3 数据范围

| 对象 | 范围来源 | 说明 |
|---|---|---|
| 推广 | `get_user_scope('promotion')` | `self`：本人创建或含本人负责客户的推广；`department`/`team`：按创建人部门/团队；`all`：全部 |
| 客户（选受众、分组成员） | `get_user_scope('customer')` | 与客户中心一致：看不到的客户，在推广中心也看不到、选不到 |
| 发件邮箱 | 原邮箱系统账号归属 | 本人绑定的邮箱；有 `promotion.use_any_mailbox` 才能选他人或公司邮箱 |

### 3.4 需要处理的旧别名（第 2 阶段，需用户确认后执行）

`permission_alias_keys()` 把 `promotion.task_create / execute / manage / create_group / edit_group / move_customer` 等都别名到 `promotion.view`：只要有查看权限，就能通过这些检查（包括设置）。处理方案：
1. 先按“当前实际效果”给已有 `promotion.view` 的角色补齐显式授权（保持现有人员能力不变，不包括新增的 `approve`）。
2. 再从别名表移除这些 `promotion.*` 别名；之后在权限中心按需收紧。
3. 新增的三个权限键不加入别名表。
该修改影响 CRM 推广现有判断，需在第 2 阶段单独提交、单独验证。

## 4. 审批规则（保留现有规则）

| 情况 | 是否需要审批 | 对应原规则 |
|---|---|---|
| 创建人有 `promotion.approve` | 不需要 | 管理员免审 |
| 创建人没有 `promotion.exempt_small` | 始终需要 | 市场始终审批 |
| 有 `promotion.exempt_small`，但使用了他人或公司邮箱 | 需要 | 业务员用他人/公司邮箱 |
| 有 `promotion.exempt_small`，邮件数超过免审额度（默认 20，设置中调整） | 需要 | 业务员超额 |
| 有 `promotion.exempt_small`，其他情况 | 不需要 | 业务员小批量 |

默认授权建议：管理员角色授予 `approve`；业务员角色授予 `exempt_small`；市场角色两者都不授予。具体由权限中心分配。

补充规则（服务端判定）：
- 提交审批或确认发送前，每个正式要用的发件邮箱都要用当前内容版本试发成功；内容修改后试发失效。
- 需要审批的推广，批准前不会开始（“马上发”“指定时间发”都在批准后生效）。
- 审批人看到提交时冻结的快照；批准后内容不可修改，需要修改时撤回重新提交。
- 退回必须填写原因；审批记录全部保留。同一推广同时只有一条待审批记录。
- 审批人不能审批自己创建的推广（有 `approve` 的人本身免审）。

## 5. 推广状态

一个推广只有一个对用户可见的状态，审批状态并入其中。

```
草稿 ──提交──▶ 待审批 ──批准──▶ 已排期 ──到时间──▶ 发送中 ──▶ 已完成
 ▲  │            │                 │                 │  ▲
 │  │            └──退回──▶ 已退回 ─┘(修改后重新提交)   │  │
 │  └──（免审）──────────────────▶ 已排期              暂停 ─▶ 已暂停
 └────────────撤回────────────────┘                 停止 ─▶ 已停止
```

| 状态 | 代码 | 说明 |
|---|---|---|
| 草稿 | `draft` | 可编辑；可发测试信 |
| 待审批 | `pending_approval` | 内容冻结；创建人可撤回 |
| 已退回 | `rejected` | 显示退回原因；可修改后重新提交 |
| 已排期 | `scheduled` | 已确认，等待开始时间；可取消 |
| 发送中 | `sending` | 正在发送或人工待办未完成；可暂停、停止 |
| 已暂停 | `paused` | 不再放行新邮件；可继续 |
| 已完成 | `completed` | 全部对象有最终结果（部分失败单独显示失败数） |
| 已停止 | `stopped` | 剩余对象标记为“未发送（已停止）” |
| 已取消 | `cancelled` | 开始前取消，没有发出邮件 |

收件对象状态：待发送、已交给邮箱系统、已发送、发送失败、结果不确定（需人工核对，不自动重发）、已跳过（附原因）、已退订。人工渠道对象：待执行、已完成（必填结果）、无法联系。

### 5.1 CRM 历史推广的状态映射

历史推广只读展示，标“CRM 历史”。由 `crm_marketing_tasks.task_status` 与执行汇总映射：

| CRM 状态 | 显示为 |
|---|---|
| `draft` | 草稿（历史，不可在新模块编辑；可“复制为新推广”） |
| `pending`、`scheduled` | 已排期 |
| `running` | 发送中 |
| `manual_pending` | 发送中（人工待办未完成） |
| `paused` | 已暂停 |
| `completed` | 已完成 |
| `partial_failed`、`failed` | 已完成（标注失败数） |
| `cancelled` | 已取消 |

CRM 队列状态映射：`scheduled` → 待发送，`sending` → 发送中，`sent` → 已发送，`failed` → 发送失败，`waiting_retry` → 待发送（重试），`skipped` → 已跳过，`cancelled` → 未发送（已取消）。

切换前 CRM 推广仍在运行，历史推广进度实时读取、不复制数据；暂停/继续等操作切换前仍在 CRM 内处理。

## 6. 客户分组

### 6.1 功能

| 操作 | 权限 | 规则 |
|---|---|---|
| 新建分组 | `create_group` | 名称必填且不重名；可见性：团队共用 / 仅自己 |
| 重命名 | `edit_group` | 仅自己可见的分组只有创建人能改 |
| 删除分组 | `delete_group` | 创建人或数据范围为全部的人；软删除，10 秒内可撤销；客户资料不受影响 |
| 加入客户 | `edit_group` | 从客户数据范围内搜索、按国家等筛选、勾选或“全选当前结果”；已在组内的显示为已加入 |
| 移出客户 | `edit_group` | 单个或批量；可撤销 |
| 移到其他分组 | `move_customer` | 批量；从本组移出并加入目标组；目标组已有的只计数不重复 |
| 复制到其他分组 | `move_customer` | 批量；保留在本组，同时加入目标组 |

- 一个客户可同时属于多个分组；成员列表显示“其他分组”标签。
- 数据范围为“本人”的人，在团队共用分组中只看到、只操作自己负责的客户，并显示“你负责的 X 个（分组共 Y 个）”。
- 推广提交时冻结名单（`pm_campaign_audience`），之后分组变动不影响已提交的推广；草稿引用的分组被删除时，草稿提示重新选择。
- 每次分组变动写 `pm_audit_logs`（操作人、分组、客户数、来源与目标分组）。

### 6.2 CRM 推广分组

第 2 阶段提供一次性“从 CRM 推广分组导入”（复制 `crm_marketing_groups` 及成员到 `pm_groups`），CRM 原分组保持不变，切换完成前 CRM 内照常使用。

## 10. 发送：使用原邮箱系统

### 10.1 现有能力（`crm_mail.php`）

- 账号：`crm_user_mail_accounts`（SMTP/IMAP、签名、发件人名）。
- 队列：`crm_mail_send_jobs`，`job_id` 唯一，重复提交同一 `job_id` 不会重复投递。
- 发送：`crm_mail_cron.php` 调 `crm_mail_send_due_jobs()` 按 `scheduled_at` 领取，`crm_mail_execute_send_job()` 发出后写入 `crm_mails` 已发送，并在客户时间线记录。
- 结果：`success` / `failed` / `unknown`（服务器已接收但回执未确认，不自动重发）/ `cancelled`；运行超过 15 分钟未更新显示为不确定。

### 10.2 本模块的做法

1. 确认快照后，为每个邮件对象生成 `pm_deliveries`，按“每个邮箱的间隔、小时上限、日上限、发送时间窗”排好计划时间。
2. 推广放行进程（并入 `crm_mail_cron.php` 的同一次运行，或独立 CLI）只把未来几分钟内到期的对象写入 `crm_mail_send_jobs`，`job_id = pm_` + 哈希（推广、对象、内容版本），`payload` 带 `customer_id` 以写客户时间线。
3. 原邮箱系统负责实际发送、写已发送、记时间线；本模块回读任务状态更新 `pm_deliveries` 与推广计数。
4. 暂停：停止放行；已放行但未开始的任务取消。停止：同上，剩余对象标记“未发送（已停止）”。已在发送的那一封无法撤回，确认框写明。
5. 发送前（放行时）再检查禁联、退订、收件邮箱是否变化；变化则跳过并记原因，不替换对象。
6. 发出的推广邮件出现在发件人自己的邮箱“已发送”里，客户回信由邮箱系统现有 IMAP 同步收取；推广详情按邮件头关联显示“已回复”（第 4 阶段）。

分批放行的原因：一次写入几百个任务会挤占发件人邮箱的“待发送”列表，也让暂停失去意义。

### 10.3 需要原邮箱系统补的接口（第 4 阶段，改动集中在 `crm_mail.php`）

| 接口 | 原因 |
|---|---|
| 按指定账号写入发送任务（调用方已校验权限） | 现有 `crm_mail_send_start()` 只能用当前会话的邮箱，后台放行没有会话 |
| 取消任务但不转草稿 | 现有 `crm_mail_send_cancel()` 取消后会生成草稿，推广不需要 |
| 附加邮件头（`List-Unsubscribe`） | 推广邮件需要一键退订头 |
| 任务来源标记（`source = promotion`） | 邮箱“待发送”列表可区分或隐藏推广任务 |

这些改动影响每天使用的邮箱系统，单独提交，回归测试普通发信、延迟发送、取消发送、报价邮件。

### 10.4 退订与屏蔽

- 推广邮件页脚和 `List-Unsubscribe` 指向本模块退订页；退订写回 CRM 联系人 `unsubscribe_email`（客户中心与 CRM 推广也会看到）。
- 放行前检查：客户禁联、联系人邮件退订、旧独立中心退订与黑名单。任一命中即不发送。
- 频控同时读取本模块、CRM 推广、旧独立中心的发送记录。
- 旧邮件中的 `promotion/track.php` 退订链接在旧目录删除前保留或转发到本模块。

## 12. 屏幕适配

目标设备：小屏笔记本（1366×768、1280×720/800，含 125% 缩放后的 1536×864）与 32 寸显示器（2560×1440，或 4K 150% 缩放后的 2560 宽）。

| 宽度 | 布局 |
|---|---|
| ≥ 2400px | 内容最宽 2280px；工作台三栏；编辑页预览 640px；分组页三栏常驻（分组 / 成员 / 添加客户） |
| 1920–2399px | 内容最宽 1760px；编辑页预览 520px；分组页三栏 |
| 1441–1919px | 标准布局：侧栏 224px，编辑页预览 440px |
| 1281–1440px | 侧栏 200px，预览 380px；分组页“添加客户”改为右侧抽屉 |
| ≤ 1280px | 侧栏自动收成 64px 图标栏（悬停显示名称）；预览 340px；成员表隐藏次要列（等级、其他分组） |
| ≤ 1024px | 单栏：预览移到表单下方 |
| 高度 ≤ 820px | 顶栏 48px，卡片与表格行距收紧，底部检查栏变薄，保证 768 高度下首屏能看到主要内容 |

- 侧栏可手动收起，记住选择。
- 字号不随屏幕放大；32 寸显示器需要更大字时使用浏览器缩放，布局按缩放后的宽度自动切换。
- 验收分辨率：1280×720、1366×768、1440×900、1920×1080、2560×1440。
