# 推广中心 V1 设计说明

状态：2026-10-13 第一阶段（设计与原型），尚无后端代码，不连接数据库，不发送邮件。

## 1. 目标与范围

- 替换独立推广中心 `promotion/`，并逐步替换 CRM 内的推广模块（`crm_marketing*.php`、`assets/crm/promotion-composer.js`）。
- 作为 CRM 按模块重构的第一个模块：独立目录、独立数据表、旧表经适配器只读，客户中心日常使用不受影响。
- 界面全新设计，不沿用 CRM 界面，也不沿用 `material_center_v1/ui/`。

## 3. 角色

角色按 `crm_roles.role_key` 明确映射，不再按角色名字符串猜测。

| 本模块角色 | role_key（待确认） | 能做什么 |
|---|---|---|
| 管理员 | `super_admin`、`admin`、`manager` | 看全部推广与历史；审批；改设置；用任意启用邮箱 |
| 市场 | `marketing` | 看全部推广与历史；创建推广（始终需审批）；不能审批 |
| 业务员 | `sales` | 只看本人创建或本人负责客户的推广；只用本人邮箱或经审批的其他邮箱 |
| 只读 | `viewer`、`finance` | 只看统计与列表，不能创建或执行 |

所有按钮的显示与否由服务端返回的“可执行动作列表”决定，提交时服务端再次校验。

## 4. 审批规则（保留现有规则）

| 情况 | 是否需要审批 |
|---|---|
| 管理员创建 | 不需要 |
| 市场创建 | 始终需要 |
| 业务员使用他人或公司邮箱 | 需要 |
| 业务员本次邮件数超过免审额度（默认 20，可在设置中调整） | 需要 |
| 业务员其他情况 | 不需要 |

补充规则（服务端判定，不由前端决定）：
- 提交审批或直接发送前，必须已发过测试信，且测试信对应的是当前内容版本；内容改动后测试信失效。
- 审批人看到的是提交时冻结的最终预览快照；批准后内容不可再改，需要改动时撤回审批重新提交。
- 退回必须填写原因；退回后创建人修改并重新提交，审批记录全部保留。
- 同一推广同一时间只能有一条待审批记录。

## 5. 推广状态

一个推广只有一个对用户可见的状态。审批状态并入其中，不再出现“待审批显示成草稿”。

```
草稿 ──提交──▶ 待审批 ──批准──▶ 已排期 ──到时间──▶ 发送中 ──▶ 已完成
 ▲  │            │                 │                 │  ▲
 │  │            └──退回──▶ 已退回 ─┘(修改后重新提交)   │  │
 │  └──（免审）──────────────────▶ 已排期              暂停 ─▶ 已暂停
 └────────────撤回────────────────┘                 停止 ─▶ 已停止
```

| 状态 | 代码 | 说明 |
|---|---|---|
| 草稿 | `draft` | 可编辑；可发测试信 |
| 待审批 | `pending_approval` | 内容冻结；创建人可撤回 |
| 已退回 | `rejected` | 显示退回原因；可修改后重新提交 |
| 已排期 | `scheduled` | 已确认，等待开始时间；可取消 |
| 发送中 | `sending` | 正在发送或人工待办未完成；可暂停、停止 |
| 已暂停 | `paused` | 不再领取新邮件；可继续 |
| 已完成 | `completed` | 全部对象有最终结果（含部分失败，单独显示失败数） |
| 已停止 | `stopped` | 剩余对象标记为“未发送（已停止）” |
| 已取消 | `cancelled` | 开始前取消，没有发出任何邮件 |

收件对象状态：待发送、发送中、已发送、发送失败、结果不确定（需人工核对，不自动重发）、已跳过（附原因）、已退订。人工渠道对象：待执行、已完成（必填结果）、无法联系。

### 5.1 CRM 历史推广的状态映射

历史推广只读展示，标“CRM 历史”。状态由 `crm_marketing_tasks.task_status` 与执行汇总计算后映射：

| CRM 状态 | 显示为 |
|---|---|
| `draft` | 草稿（历史，不可在新模块编辑；可“复制为新推广”） |
| `pending`、`scheduled` | 已排期 |
| `running` | 发送中 |
| `manual_pending` | 发送中（人工待办未完成） |
| `paused` | 已暂停 |
| `completed` | 已完成 |
| `partial_failed`、`failed` | 已完成（标注失败数） |
| `cancelled` | 已取消 |

队列状态映射：`scheduled` → 待发送，`sending` → 发送中，`sent` → 已发送，`failed` → 发送失败，`waiting_retry` → 待发送（重试），`skipped` → 已跳过，`cancelled` → 未发送（已取消）。

切换前 CRM 推广仍在运行，历史推广的进度实时读取，不复制数据；暂停/继续等操作在切换前仍回到 CRM 内处理。

## 9. 发送规则

移植 CRM 推广 v2 已验证的做法，并修复已知问题：
- 草稿保存与预览都不发送；只有确认快照后才生成队列；同一确认重复提交不产生第二份队列。
- 每封邮件使用实际发件邮箱的签名；按邮箱的间隔、小时上限、日上限排程；原子领取，防止重复发送。
- 发送前再次检查禁联、退订和收件邮箱是否变化，变化则跳过并记录原因，不替换对象。
- SMTP 已接收但结果不确定的邮件标为“结果不确定”，不自动重试（修复 CRM 推广会重发的问题）。
- 发送进程中断后，超时仍为“发送中”的记录转为“结果不确定”，由人工核对（修复卡在发送中的问题）。
- 所有时间使用北京时间显示和计算。

## 10. 新旧并行期规则

- 屏蔽检查同时读取：CRM 禁联标记、旧独立中心退订和黑名单、本模块退订。任一命中即不发送。
- 频控同时读取本模块、CRM 推广、旧独立中心的发送记录。
- 退订链接：本模块发出的邮件指向本模块；旧邮件中的 `promotion/track.php` 退订链接在旧目录下线前必须保留或转发到本模块。
- 旧独立中心 `promotion/` 的推广历史不在本模块展示（D5）；其退订与黑名单数据继续作为屏蔽依据。
