# 新建推广：流程与规则

状态：2026-10-13 按用户给的主流程整理；原型见 `prototype/`（`#/new`）。标“默认”的数值都在推广设置里可改。

## 1. 步骤

| # | 步骤 | 做什么 | 完成条件 |
|---|---|---|---|
| 1 | 推广名称 | 先写名字（内部用，客户看不到） | 名称不为空 |
| 2 | 选客户 | 选分组，或直接勾客户，两者取并集；按客户推广偏好决定走邮件还是线下；选进无归属客户时弹窗决定 | 至少一个客户；无归属客户已决定处理方式 |
| 3 | 编邮件 | 富文本：加粗/列表、超链接、图片、附件、变量；签名、空姓名称呼 | 主题、正文不为空；附件不超限 |
| 4 | 预览 | “看变量名”与“代入客户”两种模式 | — |
| 5 | 发信方式 | 按客户负责人 / 勾选邮箱均分 / 指定一个邮箱 / 手填各邮箱数量，四选一 | 方式完整（手填合计必须等于可发数） |
| 6 | 试发 | 每个正式要用的邮箱，用当前内容真发一封 | 全部邮箱试发成功 |
| 7 | 发送时间 | 马上发 / 指定时间发 / 按客户国家工作时间发；下面是全员发送计划 | 时间有效 |
| 8 | 线下明细 | 微信、微信群、WhatsApp、电话的执行清单，与邮件明细分开 | — |
| 9 | 确认 | 汇总、检查；“确认发送”或“提交审批” | 前 8 步全部完成 |

和用户原顺序的唯一差别：**发信方式放在试发和发送时间之前**。原因：试发要覆盖“正式要用的每个邮箱”，发送计划要按每个邮箱的日额度排时间，这两步都依赖先确定用哪些邮箱。

- 步骤条可以点回任意已到过的步骤修改；改了前面的内容，后面会重新计算（例如改正文会让试发失效，步骤条该步变黄）。
- 底部固定栏：上一步、当前步骤是否完成及原因、是否需要审批、保存草稿、下一步。

## 2. 规则

### 2.1 选客户与渠道

- 名单 = 所选分组成员 ∪ 直接勾选的客户，按客户去重；只包含当前用户客户数据范围（`get_user_scope('customer')`）内的客户。
- 渠道按客户推广偏好：`crm_customer_promotion_channels`（客户级）与 `crm_contact_promotions`（联系人级，含电话）。本场可以关掉某个渠道（例如这次不做电话）。
- 偏好同时有邮件和线下渠道的客户，**一封邮件 + 每个线下渠道一条**；偏好里没有邮件的，只进线下清单，并在邮件名单里标“偏好里没勾邮件，走线下”。
- 默认只发**主联系人**（`crm_contacts.is_primary`，没有则取第一个有效邮箱的联系人）；可勾“发给客户下全部有效联系人”。
- **无归属客户**（没有负责人）：选进来时弹窗，二选一并必须选：
  - 用公司市场邮箱发：需要 `promotion.use_any_mailbox`；没有“审批推广”权限的人用公司邮箱需要审批。
  - 本场排除：列入“发不了”。
  - 只有“按客户负责人”发信时才用到公司邮箱；选了其他发信方式，无归属客户跟其他客户一样分配。线下渠道的无归属客户默认由创建人执行。

### 2.2 编邮件

- 变量：`{联系人姓名}`、`{公司名称}`、`{国家}`、`{发件人姓名}`。变量按钮插在光标处（主题或正文）。
- **签名跟着发件邮箱走**：每封邮件带实际发件邮箱在邮箱系统里的签名（`crm_user_mail_accounts.signature_html`），可选“不加签名”。不做全场统一签名，避免 A 的邮箱带 B 的签名。
- **变量为空**：
  - 联系人姓名为空：可设“默认称呼”（如 Sir/Madam）；没设则这些客户**不发**，列入“发不了”。不允许发出带空白称呼的邮件。
  - 公司名称在客户中心是必填，不会为空；国家为空时 `{国家}` 同样不发（建议正文少用此变量）。
- **图片内嵌**（不外链）：外链图片在多数邮箱里默认不显示，也会被当成追踪像素。原邮箱系统已支持把正文里的图片转成内嵌附件（`crm_mail_extract_inline_data_attachments`）。单张超过 1MB 自动压缩，正文图片合计 ≤ 3MB（默认）。
- **附件**：最多 5 个，合计 ≤ 10MB（默认）。原邮箱系统单封上限是 25MB/50MB，推广是群发，按更严的值控制送达率；更大的文件改发下载链接。
- 退订链接和 `List-Unsubscribe` 信头由系统自动加，不能删。

### 2.3 预览

- **看变量名**：蓝色标出变量，发件人显示“{发件邮箱}（发信方式）”，签名显示“{发件邮箱的签名}”。
- **代入客户**：按名单逐个看成品，可上一个/下一个、下拉跳转、“只看缺姓名的”。用了默认称呼的标黄；变量为空且会被排除的标红。发件人、签名按第 5 步的发信方式显示。

### 2.4 发信方式（一场只能选一种）

| 方式 | 规则 |
|---|---|
| 按客户负责人 | 客户主负责人（`crm_customer_owners` 主负责人，或 `crm_customers.owner_user_id`）的启用邮箱发；负责人没有可用邮箱的客户列入“发不了” |
| 勾选邮箱均分 | 平均分配；**除不尽的余数每个邮箱 1 封，优先给今天剩余额度多的邮箱** |
| 指定一个邮箱 | 全部由这个邮箱发 |
| 手填各邮箱数量 | **合计必须等于可发数，对不上就不能进入下一步，不自动改**；提供“按今日剩余额度比例自动填”按钮，填完可手改 |

- 可选邮箱：本人绑定的邮箱；有 `promotion.use_any_mailbox` 才能选他人或公司邮箱（并按第 4 节审批规则触发审批）。
- 日额度与该邮箱的日常发信**共用**（按邮箱系统当天已发数计算）。超出当天额度的部分顺延到下一个工作日，不算“发不了”。

### 2.5 试发

- 正式要用的**每个**发件邮箱，都要用**当前内容版本**至少成功试发一封；改了主题、正文、图片、附件，之前的试发全部作废。
- 试发给谁：创建人填写，默认是本人邮箱，最多 5 个地址。可以选用哪个客户代入变量。
- 试发经原邮箱系统真发：主题前加 `[测试]`，不计推广量，不写客户时间线。“成功”以邮箱系统返回发送成功为准；结果不确定的不算。

### 2.6 发送时间

| 方式 | 规则 |
|---|---|
| 马上发 | 确认后 10 分钟开始；需要审批的，批准后 10 分钟开始 |
| 指定时间发 | 北京时间；不能早于现在；需要审批且批准时已过该时间，批准时必须重选，不补发 |
| 按客户国家工作时间 | 每个客户当地工作日的同一时刻（默认 09:30）；已过则顺延到下一个当地工作日 |

- 时区来源顺序：客户 `crm_customers.timezone` → 国家主营业时区（美国默认美东、加拿大多伦多、澳大利亚悉尼）→ 设置里的“默认时区”（默认北京时间）。没有国家的客户在列表里标“无国家，按默认时区”。
- 周末按国家设置：沙特、卡塔尔、科威特、阿曼、巴林、埃及等周五、周六休息；阿联酋周六、周日。国家与周末对照表放在推广设置里维护。V1 不处理各国法定节假日。
- 同一邮箱两封之间至少间隔 45 秒（默认），并受日额度限制。
- **全员发送计划**：每个对象一行——客户/联系人、收件邮箱、国家与当地时间、发件邮箱、计划发送时间（北京时间）、状态/原因。可筛选“会发 / 发不了 / 顺延或预警 / 走线下”，上方按原因汇总，可导出。
- **额度预警**：某邮箱某天的计划用量（含当天已发）达到日额度的 80%（默认）时，该邮箱当天的行标黄；超出额度顺延的行标“额度满，顺延”。

### 2.7 “发不了”原因

邮件对象（按判断顺序，命中第一条即停）：

| 原因 | 数据来源 |
|---|---|
| 客户禁联 | `crm_customers.do_not_contact`、`crm_contacts.do_not_contact` |
| 客户拒推广 | 推广偏好含 `no_promotion` |
| 客户推广已暂停 / 已停止 / 在黑名单 | `crm_customer_promotion_status.status` = `paused` / `stopped` / `blacklist` |
| 无归属客户，本场排除 | 第 2 步弹窗选择 |
| 偏好里没勾邮件（有线下渠道时走线下） | 推广偏好 |
| 联系人已离职 | `crm_contacts.is_left` |
| 无邮箱 / 邮箱格式无效 | `crm_contacts.email` |
| 已退订邮件 | `crm_contacts.unsubscribe_email` |
| 旧推广中心退订 / 黑名单 | `promo_unsubscribes`、`promo_blacklist` |
| 邮箱域名 DNS 不通过（无 MX 记录） | 发送前查询，结果缓存 24 小时；新增能力 |
| N 天内已推广过 | 频控，同时查本模块、CRM 推广、旧推广中心 |
| 与某客户同邮箱，本场只发一封 | 本场去重 |
| 联系人姓名为空，未设默认称呼 | 正文用了 `{联系人姓名}` |
| 负责人没有可用邮箱 | 按负责人发信时，负责人没有启用的邮箱账号（`crm_user_mail_accounts.is_enabled`） |

线下对象：客户级原因同上；另有“没有微信号 / 没有 WhatsApp 号码（或 `no_whatsapp`）/ 没有电话 / 没有可用于推广的客户群（`crm_customer_chat_groups.use_for_promotion = 1` 且 `status = active`）/ 联系人不接受群里联系（`avoid_group_contact`）”。

日额度满**不算**发不了，是顺延（见 2.6）。“发不了”的对象 V1 不能在本场强制发送。

### 2.8 同邮箱去重

- 本场内同一收件邮箱（不区分大小写）**只发一封**，保留名单里第一个（主联系人优先），其余标“与某客户同邮箱，本场只发一封”。
- 适用于同一公司多个联系人共用 info@，也适用于重复建档的两个客户。

### 2.9 线下明细

- 和邮件发送明细分开，单独一张清单；推广开始后进入执行人的“人工待办”。
- 每行：渠道、客户（微信群为群名及群里的本场客户）、联系方式、执行人、截止、话术（已代入变量）、复制按钮。
- **执行人默认是客户负责人**，无归属客户默认是创建人，可逐条改。
- 话术按渠道各一份模板，可用变量；`{发件人姓名}` 在线下表示执行人。
- **微信群按群合并**：同一个群里的多个本场客户只生成一条，记录发到哪个群。
- 截止：首封邮件日起 2 个工作日（默认），逾期标红。
- 完成时**必须上传截图并选择结果**（已联系-有意向 / 暂无回复 / 无兴趣 / 无法联系），不能只点完成。

### 2.10 审批与冻结

- 是否需要审批按 DESIGN.md 第 4 节（统一权限）。需要审批的，**批准前不会开始**（“马上发”和“指定时间发”都在批准后生效）。
- **点“确认发送”或“提交审批”时冻结**：名单、每个对象的发件邮箱与计划时间、内容版本、附件全部写入快照；之后分组怎么改都不影响这场。
- 退回后回到可编辑状态，修改后重新试发、重新提交。
- 确认后、开始前可以取消；已交给邮件服务器的邮件无法撤回。

## 3. 需要用户确认的默认值

1. 默认时区（无国家且无客户时区时）：原型用北京时间，是否改为其他。
2. 附件合计 10MB、正文图片 3MB、额度预警 80%、线下截止 2 个工作日、试发最多 5 个收件人。
3. “客户暂停”是否只看推广状态（`crm_customer_promotion_status`），还是也包括客户中心的客户状态（`crm_customers.status` 字典中的停用类状态）。
4. 是否需要处理各国法定节假日（V1 不处理）。
5. “发不了”的对象是否允许有审批权限的人在本场强制发送（V1 不允许）。
